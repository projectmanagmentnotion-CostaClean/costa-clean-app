# Chart Specification — Dashboard Analytics V1

## Global rules

- Chart components never query Supabase directly.
- Every series is generated by the central analytics layer.
- Use semantic Costa Clean tokens, not chart-library defaults.
- No 3D, gauge, trading, candlestick or decorative visualization.
- Tooltips expose exact values and period bucket.
- Charts have an accessible textual summary.
- Reduced motion renders final state without animated drawing.
- Missing data is distinct from zero.
- No chart implies a metric that the metric catalog marks UNVERIFIED.

## C01 — Facturado vs Cobrado vs Gastos

**Priority:** PRIMARY  
**Business objective:** understand the temporal relationship between legal invoicing, cash collection and recorded expense.  
**Recommended type:** Recharts `ComposedChart` or a simple multi-series `LineChart`/area-line combination after visual QA. Avoid mixing bars/areas only for decoration.  
**Metrics:** M01, M02, M05.  
**X axis:** normalized time bucket.  
**Y axis:** EUR.  
**Series:** Facturado, Cobrado, Gastos.  
**Range:** shared dashboard period.  
**Granularity proposal:**
- 30d → day;
- 3m → week;
- 6m → month;
- 12m/current year → month;
- custom → choose day/week/month by span using deterministic thresholds.

**Tooltip:** bucket label + exact EUR for each available series.  
**Legend:** explicit labels, keyboard/screen-reader discoverable.  
**Color:** semantic project tokens. Do not rely on color alone; tooltip/legend/series markers distinguish series.  
**Empty:** “No hay movimientos financieros en este periodo.”  
**Loading:** chart skeleton preserving final height.  
**Error:** recoverable block; unaffected KPIs remain visible.  
**Mobile:** simplified ticks, no clipped labels, tooltip usable by touch, bounded height.  
**Desktop:** dominant but max-width bounded.  
**Interaction:** optional legend visibility toggle only if accessible and state remains understandable.  
**Drill-down:** no point-click requirement in V1; section-level links to Facturas/Cobros/Gastos are safer.  
**Animation:** subtle initial reveal using existing governed motion or Recharts minimal animation; disabled under reduced motion.  
**Accessibility:** textual summary such as period totals and highest/lowest bucket; SVG title/description where supported.

## C02 — Estado financiero de facturas

**Priority:** SECONDARY  
**Business objective:** see how the selected invoice cohort is distributed across pending, partial, paid and cancelled states.  
**Recommended type:** donut when 2–4 non-zero states remain readable; horizontal stacked/bar alternative on small screens or if amount labels are clearer.  
**Metrics:** M06.  
**Primary measure:** invoice legal amount by financial state.  
**Secondary measure:** count by state.  
**Range:** invoices by issue date in selected period.  
**Tooltip:** state + amount + count + percentage.  
**Legend:** textual state + value.  
**Colors:** existing semantic status tokens; status meaning must also appear in text/shape.  
**Empty:** no invoices in period.  
**Mobile:** prefer list + compact visualization over tiny donut labels.  
**Drill-down:** open Invoices module, optionally with supported status prefilter.  
**Accessibility:** adjacent text summary of each state.

**Prohibited state:** “Vencida” until M13 is verified.

## C03 — Gastos por categoría

**Priority:** SECONDARY  
**Business objective:** identify expense concentration.  
**Recommended type:** horizontal bar as safe default because the real taxonomy can contain many categories. A donut is only allowed when the actual non-zero category count is small.  
**Metric:** M09.  
**X axis:** EUR for bar mode.  
**Y axis:** existing category labels.  
**Sort:** descending total.  
**Tooltip:** category, EUR, share of total.  
**Range:** selected period.  
**Color:** one primary/expense semantic family; avoid one arbitrary color per category.  
**Empty:** no expenses in period.  
**Mobile:** top categories with accessible “show all”/expanded list if needed; never horizontal page overflow.  
**Drill-down:** Expenses module. Category prefilter only through an existing or deliberately added navigation filter contract.  
**Accessibility:** values and percentages readable outside color.

## C04 — Top clientes por facturación

**Priority:** CONDITIONAL  
**Gate:** M01 cancellation semantics and M11 product definition accepted.  
**Business objective:** identify revenue concentration by client.  
**Recommended type:** horizontal bar/ranking, not a pie with many slices.  
**Metric:** M11.  
**Measure:** invoiced total and share of selected-period invoicing.  
**Limit:** top N chosen by responsive design; “rest” may be summarized only as an explicitly calculated remainder.  
**Labels:** human client name/display reference, never raw UUID.  
**Tooltip:** client, invoiced EUR, share.  
**Mobile:** ranking rows may be superior to a chart if labels do not fit.  
**Drill-down:** existing Client Workspace.  
**Accessibility:** ordered textual ranking accompanies visual bars.

## C05 — Servicios completados

**Priority:** OPTIONAL V1 SUPPORT  
**Business objective:** understand service completion volume across the period.  
**Recommended type:** compact bar/line series when operational volume is materially useful; otherwise show one secondary KPI and omit chart.  
**Metric:** M08.  
**Measure:** count of completed jobs by period bucket.  
**Range:** selected period.  
**Mobile:** no chart if fewer data points than a simple KPI can communicate.  
**Drill-down:** Services/Jobs module.  
**Accessibility:** total completed services and period buckets available textually.

## C06 — Clientes nuevos

**Priority:** CONDITIONAL  
**Gate:** M10 business definition accepted.  
**Business objective:** see acquisition of new client records.  
**Recommended type:** compact bars by period bucket.  
**Metric:** M10.  
**Prohibited claim:** “clientes activos históricos” unless historical-state semantics are later introduced.  
**Drill-down:** Clients.

## Recharts decision

Recharts is the proposed chart engine because Analytics V1 requires responsive multi-series charts, axes, tooltips, legends and accessible SVG composition beyond the repository's existing lightweight SVG chart guidance.

It is **not installed in this planning phase**.

Before installation, the implementation sprint must verify:

- package compatibility with React 19/Vite 8;
- bundle impact;
- responsive container behavior;
- accessible fallback strategy;
- no conflict with V3 CSS;
- tree-shaking/import discipline.

Charts must be wrapped in Costa Clean components so a future engine swap does not leak Recharts APIs through the product.
